# 归档索引（`docs/archive/`）

这里放的是**历史材料**：曾经在仓库正文位置、但已经不参与当前实现的文件。
共同约定只有一条：**归档不是当前事实源**，任何数值、版本、接口以代码与
[`docs/FACTS.md`](../FACTS.md) 为准；这里的文件名、章节号、测试数字都是当时的读数。

## 1. 为什么保留而不是删除

这些材料记着「当时为什么那样改」：某人踩过的坑、量测出来的数字、验收时的截图。
删掉之后 git 历史还查得到，但没人会再去翻；留在正文位置又会让日常 `git diff`、目录浏览
被历史噪音淹没。所以统一移到本目录，**保留内容、移出视线、在文档里写明来龙去脉**。

判据来自体检清单 `docs/HEALTH_CHECK.md` §4.3 的 P2-1 / P2-2 / P2-5；那份清单同时也是
「为什么这四项值得做」的证据台账。

## 3. 怎么用这些材料

- **写论文 / 答辩讲「演进过程」**：先看 `dsh-kanban-summary.md` 的卡片清单，需要细节再按 `id`
  回 JSON 查 `note`；
- **复现某轮排障**：`HANDOFF_HISTORY.md` 里的命令是当时的路径与参数，路径可能已经变，
  按当前仓库结构调整后再执行；
- **查「某个界面改前什么样」**：`screenshots/<主题>/`，每个目录的 README 写明基线提交与改动提交。

## 5. 新增归档的规矩

1. 用 `git mv` 移动（保住文件历史），不要「复制一份再删原文件」；
2. 在本文件 §2 表里加一行：**是什么 / 什么时候产生 / 为什么留**，三列都要有；
3. 如果原位置有文档引用它，**同一次提交里把所有引用路径改对**，不要留下打不开的链接；
4. 归档文件名带上能定位的时间或版本（例如 `dsh-kanban-2026-11-01.json`），避免以后出现
   `xxx-old.json`、`xxx-old2.json` 这种无法判断先后的名字。
