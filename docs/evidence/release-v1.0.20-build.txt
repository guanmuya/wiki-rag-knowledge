## 2. 环境（换工作区后从零重建）

本轮的构建环境起初是**空工作区**：没有 `.venv`、没有 `frontend/node_modules`、也没有
`frontend/release/`。按下面两步重建（与 v1.0.19 实测一致）：

```powershell
# 仓库根目录：后端（本机 pip 默认源是清华镜像，缺本项目锁定的未来版本包，必须显式指定官方源）

  -c backend/constraints.txt -i https://pypi.org/simple
```

## 6. 本轮没做的事（如实记录）

| 项 | 状态 | 原因 |
| --- | --- | --- |
| 建 `v1.0.20` tag | **没做** | tag 要打在 `master` 的合并提交上，由平台在合并落地后创建；本轮建会指到非合并提交 |
| 上传 GitHub Release | **没做** | Release 必须挂在 tag 上，tag 还不存在；`gh release create --verify-tag` 的完整命令见 `docs/RELEASE_NOTES_v1.0.20.md` §2 |
| 代码签名 | **没做** | 属外部凭据，需用户单独授权；现状与风险见 `docs/UPDATE.md` §6.2 |
| 改业务代码 | **没做** | 发版任务边界；`backend/app/**` 只有 `VERSION` 一行，#32 逻辑此前已合入 `master` |
| `--publish always` | **没用** | 它会在 Release 不存在时自己建 Release 并连带打 tag；构建命令是 `node scripts/build.mjs`（`--publish never`） |

## 7. 合并落地后要做什么（命令已写好，照抄即可）

完整步骤与三项校验在 [`docs/RELEASE_NOTES_v1.0.20.md`](../RELEASE_NOTES_v1.0.20.md) §2，摘要：

```powershell
# 0) 先确认 tag 已在远端（由平台在合并后创建），并确认 Release 正文取 §1 代码块而非整份文件
git ls-remote --tags origin | Select-String 'v1\.0\.20'

# 1) 把 RELEASE_NOTES_v1.0.20.md §1 的 markdown 代码块另存为无 BOM 的 UTF-8 临时正文文件，
#    再建 Release 并上传三个资产；--verify-tag 保证 tag 不存在时直接失败，不会顺手建 tag
gh release create v1.0.20 --verify-tag --title "v1.0.20" --notes-file .tmp-release-body.md `
  frontend/release/updates/latest.yml `
  frontend/release/updates/wiki-rag-knowledge-1.0.20-x64-setup.exe `
  frontend/release/updates/wiki-rag-knowledge-1.0.20-x64-setup.exe.blockmap

# 2) 匿名可下载性（三个都应为 200；刚上传后 1–2 分钟 CDN 延迟属正常）
$base = 'https://github.com/guanmuya/wiki-rag-knowledge/releases/download/v1.0.20'
foreach ($f in @('latest.yml','wiki-rag-knowledge-1.0.20-x64-setup.exe','wiki-rag-knowledge-1.0.20-x64-setup.exe.blockmap')) {
  "$f -> $(curl.exe -sIL -o NUL -w '%{http_code}' "$base/$f")"
}
```

> 换机器重建：`cd frontend && node scripts/build.mjs`。前提是 Node 22+ 与 pnpm、能联网下载
> Electron 二进制与 NSIS 工具链，以及一个装了 `backend/requirements-build.txt` 的 Python 环境
> （默认取仓库根 `.venv`，可用 `WRK_PYTHON` 覆盖）。构建**不会**改变 `latest.yml` 之外的任何仓库文件；
> 重建后 sha512 与体积必然变化，上传前请以本文件 §5 或现场重算的值为准，逐项核对 `latest.yml`。
