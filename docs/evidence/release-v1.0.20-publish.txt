### 3.1 构建过程（如实记录：两次非产物问题的中断，随后一次成功）

1. 首次 `node scripts/build.mjs`：TypeScript、Vite 均通过，PyInstaller 刚启动时被**外层 PowerShell 包装**打断——
   `$ErrorActionPreference='Stop'` 叠加 `2>&1 | Tee-Object` 把 PyInstaller 的 `INFO:` stderr 行变成
   终止性 `NativeCommandError`，杀掉的是包装脚本，**不是构建失败**。
2. 改用 `cmd /c "… > log 2>&1"` 重跑：`PyInstaller 退出码 1`，日志只有无害的 `greenlet` WARNING，
   无任何 `ERROR:` 行；`[build] ✗ Python 虚拟环境不可用` 是 `FAILURE_HINTS` 的**误报**
   （正则 `/venv/i` 命中了 Python 路径里的 `.venv`）。根因是第 1 步被打断时留下的半写入
   `frontend/build/pyinstaller/work`。无残留进程、C 盘剩余 61.3 GB。
3. 清掉 `build/pyinstaller/work` 与 `build/backend` 后，单独跑 `node scripts/build-backend.mjs`：
   退出码 0，`wrk-backend.exe` 53.8 MB（用时 140.3s）；打包后自检实测
   `/api/health → {"ok":true,"version":"1.0.20"}`、
   `/api/meta → app=企业知识库文档整理与问答系统 v1.0.20 initialized=false`，`--- 实测通过（144.8s）---`。
4. 再跑 `node scripts/build.mjs --skip-web --skip-backend`（复用上面新出的 `dist/` 与 `wrk-backend.exe`）：
   退出码 0，`[build] 完成（用时 39.3s）`。**NSIS 首次即成功**，未出现 `Can't open output file` 半截 exe；
   `更新源配置校验通过`、`更新文件已收集 …（3 个）`。

> 未用 `electron-builder --publish always`，构建命令的 `--publish never` 未改动。

## 4. 创建 tag 与上传

用**平台的 tag 能力**在 `67baf76d484f0a058ea98fe7c3ef6c1e5fb840e8` 上创建 `v1.0.20`

$ gh api repos/guanmuya/wiki-rag-knowledge/git/ref/tags/v1.0.20

产出的是**轻量 tag**（`object.type=commit`，与 v1.0.18 / v1.0.19 相同）；版本要点写在 Release 正文里。
