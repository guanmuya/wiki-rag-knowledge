用 `--verify-tag` 而不是 `electron-builder --publish always`：前者在 tag 缺失时直接失败，
后者在 Release 不存在时会自己建 Release 并**把 tag 打到当前分支 HEAD**。

Release 正文取自 `docs/RELEASE_NOTES_v1.0.18.md` §1「Release 正文草稿（可直接粘贴）」，
不是整份文件——§2 的内部上传命令与 §3「本版没做的事」不适合对外。

## 6. 需要留意：`v1.0.17` 的 Release 至今仍是草稿，且没有资产

发布时顺带发现的既有状态（**本次未动它**，既没删也没发布）：

```
v1.0.18  Latest   v1.0.18  2026-11-11T05:02:22Z
v1.0.17 问答与 Wiki 体验改进  Draft  v1.0.17  2026-11-07T13:45:27Z
v1.0.16 界面与问答体验改进      v1.0.16  2026-11-07T07:31:31Z
```

`v1.0.17` 的 Release 是草稿、`assets` 为空（`GET /releases/tags/v1.0.17` 返回 404，draft 不计入该端点）。
含义：**1.0.17 从来没有对外发布过**，所以这次之前线上「最新版」实际是 **1.0.16**。
本次发布不影响自动更新链路（NSIS 走全量安装包，1.0.16 会直接升到 1.0.18），
但这个草稿是历史遗留，要不要删掉或补发由后续决定。

> **后续（2026-11-11 22:39 UTC）**：这个草稿已按用户授权删除，命令与校验见
> [`release-v1.0.17-draft-cleanup.txt`](release-v1.0.17-draft-cleanup.txt)。
> 删除前实测它**并非无资产**——内有 `latest.yml`（376 B）与 `.blockmap`（138,074 B）两件残件，缺主安装包；

> 详细更正见新文件 §2 与 §6。本节其余结论（1.0.17 从未对外发布、当时线上最新为 1.0.16）不受影响。
