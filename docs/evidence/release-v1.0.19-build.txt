## 2. 环境（换工作区后从零重建）

本轮的构建环境是**空工作区**：开始时没有 `.venv`、没有 `frontend/node_modules`、也没有
`frontend/release/`。按下面两步重建（这是 `docs/UPDATE.md` §3 之外的实测补充）：

```powershell
# 仓库根目录：后端（本机 pip 默认源是清华镜像，缺本项目锁定的未来版本包，必须显式指定官方源）
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip -i https://pypi.org/simple
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt -r backend/requirements-build.txt `
  -c backend/constraints.txt -i https://pypi.org/simple

# frontend/ 目录：前端
pnpm install --frozen-lockfile
```

> 说明：CI 只用 `requirements-dev.txt`（测试分组），打包要 `requirements-build.txt`（带固定版本 PyInstaller）。
> 本次把两组装进同一个 `.venv`，`build-backend.mjs` 自校验 `PyInstaller: 6.11.1（与锁文件一致）` 通过。
> Playwright 的 Chromium 与 Electron 二进制来自本机既有缓存（`%LOCALAPPDATA%\ms-playwright`、
> `%LOCALAPPDATA%\electron\Cache`），没有重新下载。

## 7. 合并落地后要做什么（命令已写好，照抄即可）

完整步骤与校验在 [`docs/RELEASE_NOTES_v1.0.19.md`](../RELEASE_NOTES_v1.0.19.md) §2，摘要：

```powershell
# 0) 先确认 tag 已在远端（由平台在合并后创建）
git ls-remote --tags origin | Select-String 'v1\.0\.19'

# 1) 建 Release 并上传三个资产；--verify-tag 保证 tag 不存在时直接失败，不会顺手建 tag
gh release create v1.0.19 --verify-tag --title "v1.0.19" --notes-file docs/RELEASE_NOTES_v1.0.19.md `
  frontend/release/updates/latest.yml `
  frontend/release/updates/wiki-rag-knowledge-1.0.19-x64-setup.exe `
  frontend/release/updates/wiki-rag-knowledge-1.0.19-x64-setup.exe.blockmap

# 2) 匿名可下载性（三个都应为 200；刚上传后 1–2 分钟 CDN 延迟属正常）
$base = 'https://github.com/guanmuya/wiki-rag-knowledge/releases/download/v1.0.19'
foreach ($f in @('latest.yml','wiki-rag-knowledge-1.0.19-x64-setup.exe','wiki-rag-knowledge-1.0.19-x64-setup.exe.blockmap')) {
  "$f -> $(curl.exe -sIL -o NUL -w '%{http_code}' "$base/$f")"
}
```

> 换机器重建：`cd frontend && node scripts/build.mjs`。前提是 Node 22+ 与 pnpm、能联网下载
> Electron 二进制与 NSIS 工具链，以及一个装了 `backend/requirements-build.txt` 的 Python 环境
> （默认取仓库根 `.venv`，可用 `WRK_PYTHON` 覆盖）。构建**不会**改变 `latest.yml` 之外的任何仓库文件。
